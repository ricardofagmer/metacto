# ADR 0008 — Heuristic duplicate scores are calibrated onto the port's threshold scale

Date: 2026-10-06
Status: accepted

## Context

`FindDuplicatesInput.threshold` defaults to `DEFAULT_DUPLICATE_THRESHOLD = 0.6`
(`packages/shared/src/intelligence-port.ts`). The prompt for the Anthropic adapter
defines `similarity` as the model's confidence that two requests would be merged:
0.8 or above for clear duplicates, 0.4 to 0.6 for related, below 0.3 for unrelated
(`apps/api/prompts/dedupe.md`). The heuristic adapter measures TF-IDF cosine
similarity over stemmed, stop-word-filtered title and description terms
(`apps/api/src/intelligence/providers/heuristic/text-vectors.ts`,
`heuristic-dedupe.ts`).

Those two numbers are not on the same scale. Cosine between two short,
independently worded requests that share a few content words rarely reaches 0.6
even when they are paraphrases. The first golden-set run
(`apps/api/evals/RESULTS.md`, history row `golden@1` / `heuristic-dedupe@1`)
shows the consequence: at the shared default threshold the heuristic returned no
expected duplicate at all. The sweep in `apps/api/evals/README.md` ("Heuristic
dedupe calibration") records where real duplicates and the closest same-topic
near misses sit on the raw cosine scale, and which alternative signals were tried
and rejected. The numbers live in those two files and are regenerated by
`pnpm --filter @fis/api eval`; this ADR cites them rather than copying them.

## Decision

The heuristic provider keeps its own calibration point and maps its raw cosine
onto the caller's scale, so that a caller threshold means the same thing for
every provider and the port contract does not change.

- `HEURISTIC_COSINE_AT_DEFAULT_THRESHOLD` (`heuristic-dedupe.ts`) is the raw
  cosine that corresponds to the port default of 0.6. It is fitted on the golden
  set as the midpoint of the gap between the strongest labelled near miss and the
  weakest true duplicate.
- `cosineToCallerScale` is piecewise-linear and monotonic: `[0, anchor]` maps to
  `[0, 0.6]` and `[anchor, 1]` to `[0.6, 1]`. Ranking is unchanged; only the
  reported scale moves.
- `findHeuristicDuplicates` translates the caller's threshold to the cosine scale
  with `callerScaleToCosine` before ranking, then reports each candidate's
  `similarity` on the caller scale and filters once more on the caller's
  threshold, so every returned candidate satisfies `similarity >= threshold`.
- The rationale string still shows the raw cosine and states that it is a
  heuristic match, not a language-model judgement.
- The Anthropic adapter's candidate preselection (`rankSimilarRequests` at
  threshold 0, ADR 0003 amendments) stays on the raw cosine scale; only the
  heuristic provider's output is calibrated.
- Changing the anchor, the tokenizer, the synonym table or the golden set means
  bumping `HEURISTIC_VERSIONS.findDuplicates` (`heuristic-versions.ts`, currently
  `heuristic-dedupe@2`), re-running the golden set and committing the new
  `RESULTS.md` and `history.json` row. Golden labels are never edited to make a
  threshold pass (`golden.json` notes); a new case is added instead.

## Alternatives rejected

- A separate, lower raw threshold inside the heuristic (ignore the caller's
  0.6): callers and the evals would then see similarities on two different
  scales, and the spec's separation targets (duplicates at or above 0.6, distinct
  pairs below 0.4) could not be checked uniformly across providers.
- Lower the shared `DEFAULT_DUPLICATE_THRESHOLD` for both providers: it would make
  the Anthropic adapter return "related but distinct" pairs (0.4 .. 0.6 by the
  prompt's own scale) as duplicates.
- Blend cosine with title or description Jaccard, or add stem bigrams: every
  blend swept in `evals/README.md` reduced the duplicate/near-miss gap, because
  title overlap is exactly what same-topic near misses share.
- Replace TF-IDF with embeddings for the no-key path: the no-key path must work
  offline (ADR 0003); embeddings are the pgvector production path (ADR 0002).

## Consequences

- The calibration gap is thin and fitted to a handful of positives
  (`evals/README.md`); it is a measured floor, not a quality claim. One golden
  near miss ("Reset password by SMS" vs the password-reset-email bug) is a known
  lexical limitation left in the golden set rather than tuned away.
- A heuristic `similarity` of 0.6 and an Anthropic `similarity` of 0.6 now mean
  "at the merge threshold" for both, but they are produced by different evidence;
  the provider label (ADR 0009) tells the reader which one applies.
- The evals' "precision/recall at default threshold 0.6", near-miss and
  separation checks apply the same cut to both providers (`evals/scorers.ts`).
